# 概念

## PIC 和 pic 的区别

\-fpic 在某些平台上有一些限制，如有 GOT 表大小限制，全局符号数量限制，代码长度限制等，而 \-fPIC 则没有这些限制，通常都使用 \-fPIC。

## PIC 和 PIE 的区别

PIE 可用于生成地址无关的二进制。使可执行程序在内存中加载时可以被加载到任意地址，而不依赖固定的内存位置。核心作用是增强程序的安全性。PIC 主要用于代码库。

## 如何看是否 PIC

`readelf -d foo.so | grep TEXTREL`

PIC 的动态库不会包含任何代码段重定位表的。

## 链接符号和调试符号

链接符号用于链接时重定位，ELF 文件一定包含的。

调试符号用于 GDB 跟踪展示，可以被 strip。

nm 默认看的是链接符号，不是调试符号。

## 如何判断是否有调试符号？

1. nm \-\-debug\-syms 打印 debug 符号。

2. file 查看是否有 with debug\_info， not stripped。

3. readelf \-S 看是否有 。debug 开头的段。

# 动态库去链接静态库

动态库默认是 \-fPIC 的，而静态库默认是地址有关的，二者无法直接链接。

- 可以通过生成地址有关的动态库去链接静态库，不过动态库没法共享一份内存的代码了。

- 另外把静态库编译为地址无关的也是可以的。

\-fPIC 是编译选项也是链接选项，如果编译的时候加了 fPIC，链接的时候也必须加上，动态链接器需要在启动时填 GOT 表。

在链接时，本地变量会完成重定位，以消除这部分的重定位条目。而跨模块符号，比如 \.o 中的全局变量，调用其他 \.so 的符号等，链接器会建立 GOT 表项，等动态链接器加载时，完成重定位。

# 链接静态库和 object file 的区别

假如有如下文件：

```ProtoBuf
a.o // 有函数 f() {std::cout << "a.cc" << std::endl}
b.o // 有函数 f() {std::cout << "b.cc" << std::endl}
liba.a // 包含 a.o
libb.b // 包含 b.o
main.cc // 调用函数 extern f()
```

1. g\+\+ \-o main main\.cc a\.o b\.o 会报符号重定义吗？

会。a\.o 和 b\.o 都有 f\(\) 定义。

2. g\+\+ \-o main main\.cc  \-lb \-la 会报符号重定义吗？如果不会，输出什么？

不会。不同于所有的 \.o 文件最终都会编译到二进制产物，静态库链接为了减少二进制体积，只会把被引用符号所在的 \.o 文件链接进来。虽然 liba 和 libb 有相同的符号，但链接器会使用第一个扫描到的 libb 中的 f\(\)，liba 中的符号不会被链接进来。  

# 动态库符号重定义

和多个 \.o 文件不同，动态库是可以有重复的定义，GOT 就是用来做多个定义的对象替换的。



动态库对相同符号的处理：

动态库中定义的 class static 变量，本着 one define rule， 从 so 的视角，不知道这个对象是定义在其他动态库，还是定义在主程序中，甚至定义在同 so 的其他 \.o 文件中。动态库都会把全局变量、static 变量当做定义在外部模块，然后通过 GOT 引用。动态链接时，发现主程序中定义了这个 static 变量，就会把 GOT 中的地址重新指向主程序中的副本。



多次析构问题：

从主程序看，定义了 static 变量，肯定是要注册析构程序的。

从 so 视角，外部模块不一定有定义 static 变量，自己的副本也是要析构的，只是现在副本的指针被替换为了主程序中的对象。
